# Technical notes on reproducing the analyses

I record the analysis that the present files actually describe. The original core script is sequential and uses `saveRDS`/`readRDS` checkpoints, but it is not a one-command portable workflow: its data, output directories and some figure inputs remain outside this repository. These notes describe the recorded settings and input requirements; they are not evidence of a fresh model rerun.

| Step | Input and expected format | Verified setting or distinction | Saved output and how I would run it | Resource/status |
| --- | --- | --- | --- | --- |
| RADseq panel and structure | Stacks VCF aligned to the *Ameiva* assembly; sample metadata CSV; individual CHELSA CSV | I retain 245 individuals, variants with ≤30% missingness and at least three copies of each allele, and exactly 14,134 SNPs. The core script then performs imputation, sNMF (main K=4) and PCA. | `analysis/01_core/RDA-2027-bonferroni.R` writes `02_Ameiva_245_missing30_MAC3.vcf.gz`, `03_genotype_matrix_14134.rds`, imputed `.lfmm`, sNMF and PCA outputs. | Expensive; raw inputs and checkpoints are external. |
| Main partial RDA | Aligned 245 × 14,134 imputed allele matrix; standardized climate; PC1–PC3, longitude and latitude; alternative sNMF control | The response is the allele matrix. Four selected predictors are BIO2, BIO3, BIO14 and BIO13. The principal geographically conditioned model is `geno_complete ~ climate + Condition(PC1 + PC2 + PC3 + lon + lat)`; a sNMF + geography model provides the candidate consensus. Locus scanning uses `p < 0.01/14,134`; the strict landscape set additionally requires 3 SD and contains 626 SNPs. | The core script writes `07_RDA_*`, `08_RDA_locus_scan_*`, `08_RDA_candidates_landscape_consensus.csv` and `08_RDA_candidates_landscape_strict_3SD.csv`. | Expensive; the full genotype matrix and validated selection outputs are external. |
| LFMM2 and linear consensus | Same imputed matrix; each selected climate predictor as a one-column matrix | `LEA::lfmm2` uses K=4 selected from sNMF; `lfmm2.test(..., genomic.control=TRUE)` is followed by BH q ≤ 0.05. The intersection of LFMM2 with the pRDA landscape consensus has 164 SNPs. | The core script writes `09_LFMM2_all_14134.csv`, `09_LFMM2_candidates_FDR05.csv` and evidence tiers. | Expensive. The saved signed-effect recovery is separately documented; it reproduces original z scores and P values. |
| Controlled full-panel GF | Imputed 245 × 14,134 matrix; ten CHELSA predictors BIO1–BIO7, BIO12, BIO13 and BIO15; genome-wide PC1–PC3 and coordinates | `GF_14134_bruto_controlado_8cores.R` fits raw dosages and residualized/SD-scaled dosages. It assigns SNP names round-robin to 32 **computational** batches (22 with 442 SNPs, 10 with 441), uses six workers, 500 trees per response, `mtry=3`, `maxLevel=0`, `nbin=101` and seed 2027 plus batch offset. Its top 5% of controlled OOB R² contains 707 loci. | The GF script writes the block registry, raw/controlled `.rds` objects, combined models, SNP OOB-R² and predictor-importance summaries. I would run it only after the core matrices and climate table are verified. | Very expensive; large blocks and combined models remain external. The historical 118-SNP, four-predictor candidate GF is a different model and must never replace this fit in full-panel claims. |
| Main RDAforest | Genome-wide distance `1 - cor(t(geno_complete))` from the 14,134 SNPs; selected climate; geographic-distance coordinates and PC1–PC3 | The core script conditions `capscale` on two geographic axes and PC1–PC3. Its recorded piecewise elbow retains eight genomic axes. `mtrySelJack` uses 31 replicates, OOB 0.20 and 1,500 trees; `ordinationJackknife` uses 25 replicates and 1,500 trees. The saved importance table contains BIO13, BIO3 and BIO2. | The core script saves the `12_RDAforest_*pcs8.rds` fit and importance/diagnostic tables. A 15-PC run is a sensitivity, not the main model. | Very expensive; fitted objects and spatial predictions remain external. |
| Annotation | *Ameiva* assembly GCA_046270845.1, *Aspidoscelis tigris* GCA_023333525.2 genome/GFF, VCF SNP coordinates | `prepare_liftoff_ameiva.sh` runs Liftoff; the output GFF records v1.6.3 and `-p 4` with default coverage/identity thresholds 0.50. The core script uses `GenomicRanges` for gene/exon/CDS overlap and nearest-gene distance. An overlap with two distinct genes retains the last GFF-order hit; it is not a biological tie-break. | The shell script writes transferred GFF/unmapped IDs; the core script writes `10_annotation_14134.csv`. Full counts and caveats are in `provenance/LIFTOFF_METHODS_RECORD.md`. | Genome download/transfer is substantial; assemblies and GFF are external. |

## Order and checkpoints

I would verify raw sample identities and permissions first, then run the core script through filtering, structure, predictor selection, pRDA/LFMM2, RDAforest and annotation using its saved checkpoints. I would then run the separate 32-batch full-panel GF, its present/future projection scripts, the figure scripts, and finally compare saved displacement maps. Before reproducing any figure I would check its exact saved inputs and model lineage in [the five-figure inventory](figure_inventory.md). I do not rerun a heavy model merely because a later plot has changed.

After acquiring the external inputs and reviewing path assignments, the script entry points are, in order:

```bash
Rscript analysis/01_core/RDA-2027-bonferroni.R
Rscript analysis/04_gradient_forest/GF_14134_bruto_controlado_8cores.R
Rscript analysis/06_projection/build_nonlinear_present_landscapes.R
Rscript analysis/06_projection/project_controlled_GF_future_offset_7cores.R
Rscript analysis/09_figures/make_Figure3_nonlinear_models_v4.R
Rscript analysis/10_candidate_directionality/07_candidate_directionality_figure_v5.R
```

This is an execution order, **not** a claim that these commands currently succeed in a fresh checkout. The first two can use substantial memory, disk and CPU; the projection steps are raster-heavy. Liftoff is a separate shell step (`analysis/07_annotation/prepare_liftoff_ameiva.sh`) that downloads assemblies and writes a transferred GFF. Figures 4 and 5 currently require finishing scripts outside this repository, so I do not give a misleading in-repository command for them.

No accession or scenario identifier is supplied here unless supported by an inspected source. The missing artifacts and public-release decisions are listed in [data availability](data_availability.md) and [the checklist](release_checklist.md).
